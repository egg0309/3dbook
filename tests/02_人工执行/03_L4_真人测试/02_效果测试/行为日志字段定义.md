# 行为日志字段定义（L4 埋点口径）

> 对应实现：`3dbook/server/app/store.py`（SQLite `attempts` 表，匿名、幂等写入）
> 目的：让“行为日志”能被复核——每个统计数字都能追回一条会话记录。

---

## 一、采集边界

| 项 | 规定 |
| --- | --- |
| 匿名编号 | 浏览器本地生成 `zunyi.clientId`（localStorage），同浏览器多次测试归并为同一编号 |
| 会话编号 | 每次“开始推演”生成 `sessionId`；点「重新推演」换新会话，产生新行 |
| 存储位置 | 本机 `server/data/sessions.db`，WAL 模式；`*.db` 已加入 `.gitignore`，永不入库 |
| 公网查询 | **不开放**任何公网查询接口；只允许本机导出 |
| 导出方式 | 双击 `server/export.bat`，或在 `server` 目录的 `.venv` 中执行 `python -m app.export`；同时生成 `data/export-<时间戳>.csv` 与 `export-<时间戳>.html`。CSV 为 UTF-8-SIG（Excel 中文不乱码），HTML 可直接用浏览器打开查看 |
| 批次归档 | 正式发问卷前双击 `server/archive.bat`（或 `python -m app.archive`）：把当前 `sessions.db` 整体移到 `data/archive/sessions-<时间戳>.db`，并新建空库；旧批次不删除，仍可用 `python -m app.export --db data/archive/sessions-<时间戳>.db` 导出查看 |
| 服务守护 | 双击 `server/keepalive.bat` 启动后台守护：每 15 秒检查前端 5173 与后端 8000，掉线自动拉起；日志在 `server/logs/keepalive.log` |
| 导出内容 | 选项显示为“代号 + 中文标签”（如 `1A 追问老陈…`），时间统一北京时间，状态自动归类为“已完成 / 中途退出（停在第X关）/ 只开始未作答”，并附汇总卡片与各关选择分布 |
| 故障策略 | 写库异常只记日志，不影响对话；日志缺失的会话不能计入统计，须在报告中说明缺失量 |

## 二、字段表（`attempts` 表 / 导出 CSV 列）

| 字段 | 含义 | 用途 | 缺失处理 |
| --- | --- | --- | --- |
| `client_id` | 匿名编号 | 同一受试者多次会话归并 | 空值行标注“无编号”，不强行归并 |
| `session_id` | 单次推演会话 | 去重与幂等 | 主键，不会缺失 |
| `started_at` | 点击「开始推演」的时间（UTC） | 计算时长 | 若缺失，用 `first_turn_at` 兜底并注明 |
| `first_turn_at` | 首次作答时间 | 兜底计算时长 | —— |
| `finished_at` | 完成三关并生成复盘的时间 | 完成率 | 空 = 中途退出，算“未完成” |
| `duration_seconds` | 完成时 = `finished_at − started_at` | 平均完成时长 | 未完成不计算时长，不补 0 |
| `stage` | 最新关卡（`level1/2/3/review/done`） | 流失漏斗 | —— |
| `choices_json` | 累计选项（合并而非覆盖） | 路径分析 | 重试同关以最新一次为准 |
| `answers_json` | 按关卡的 `{stage: {choice, ts}}` | 各关作答与停留 | 中途退出保留已答部分 |
| `fallback_count` | 触发兜底的次数 | 稳定性指标 | —— |
| `report` | 复盘全文 | 质性材料 | 未生成则空 |
| `updated_at` | 最近一次更新 | 数据新鲜度 | —— |

> 导出层还会补充两类派生列（不额外入库）：`同编号第几次`（同一 `client_id` 按时间排序的第几次会话）；`第1/2/3关用时`、`复盘用时`（相邻作答时间戳之差，包含阅读、思考与等待反馈时间，缺失段留空不补 0）。

> ⚠️ 已知限制（写进报告“风险”节）：**同一关重选只保留最后一次选择**，早期选择被覆盖；因此“是否重选”只能从 `fallback_count` 与时间差间接推断，不能精确统计。若需要完整路径，须在下一版增加事件流水表。

## 三、漏斗与指标口径

| 指标 | 定义 | 数据来源 |
| --- | --- | --- |
| 开始推演人数 | `started_at` 非空的去重 `client_id` 数 | attempts |
| 三关完成率 | `finished_at` 非空 / 开始推演人数 | attempts |
| 各关流失 | 最后 `stage` 为 `level1/2/3` 的人数分布 | attempts |
| 平均作答时长 | 完成会话的 `duration_seconds` 均值（中位数一并报告） | attempts |
| 各关用时 | 相邻作答时间戳之差，用于看每关停留与流失位置 | attempts + answers_json |
| 同一人多次测试 | 同一 `client_id` 的会话按时间标为第 1、2… 次 | attempts |
| 兜底率 | `fallback_count > 0` 的会话数 / 总会话数 | attempts |
| 选择分布 | 按 `answers_json` 统计各关 A–D 频次 | attempts |
| 复盘生成率 | `report` 非空的完成会话 / 完成会话 | attempts |

## 四、与前后测的配对

- 施测时把匿名编号写在纸质前后测卷与问卷上，同时让受试者在**同一浏览器**完成体验；
- 数据录入时用 `client_id` ↔ `participant_id` 建立映射表（该映射表单独保存，不进仓库）；
- 无法配对时如实标注“未配对”，**不得用平均值代替个体配对**做前后测 t 检验。

---

## 五、隐私与合规

1. 不采集姓名、学号、手机号、IP、人脸；
2. 知情同意书须写明采集范围、用途、保存期限与删除方式；
3. 报告与答辩材料只出现匿名编号与原话摘录（脱敏）；
4. 测试结束后，按知情同意书承诺的期限删除 `sessions.db` 与导出 CSV。
