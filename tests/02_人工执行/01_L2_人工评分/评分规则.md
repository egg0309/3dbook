# L2 生成质量人工评分规则

> 适用：`01_机器执行/02_L2_生成采样/runs/L2_runs_*.jsonl` 中的每条生成结果。
> 原则：**脚本只采样与初筛，四个维度的最终判定由人做**；判 1 或 0 都必须在备注里留依据。

---

## 一、样本构成（30 条 × 5 次采样 = 150 条记录）

| 类别 | 样本编号 | 数量 | 判分重点 |
| --- | --- | --- | --- |
| 关卡反馈 | `F1-1A` … `F3-3D` | 12 | 证据包约束、老陈口吻、分层引导 |
| 复盘总评 | `RV-seeker` / `RV-growing` / `RV-cautious` / `RV-warm` | 4 | 画像贴切、不逐题复盘、谈心结构 |
| 答疑（RAG） | `QA-01` … `QA-14` | 14 | 命中正确史料、必答要点、超纲安全拒答 |

每条样本重复采样 5 次（temperature 0.7 有随机性），逐次独立判分，不合并、不取最好一次。

---

## 二、四个维度（每项只填 1 / 0）

### 1. 史实忠实度 `fact_fidelity`

| 判 1 | 判 0 |
| --- | --- |
| 所有人物、时间、数字、事件都能在证据包 / 知识库中找到依据 | 新增或改写史实；把“部分回忆材料”说成确定事实；编造数字、人名、会议细节 |
| 反馈只围绕本题 `fact_points`，没有跑题扩展 | 越出本题证据包讲别的史实，或与知识库条目矛盾 |
| 答疑命中正确知识条目并覆盖必答要点 | 命中错误条目、遗漏必答要点，或对超纲问题输出后续史实 |

常见 0 分例（须写进备注）：
- 把“凯丰说毛泽东照着两本书打仗”直接写成“照着《三国演义》打仗”而未注明仅有部分回忆材料；
- 老陈台词报出“损失两万多人”一类精确数字（老陈在场外，不掌握精确数字）；
- 超纲问题（遵义会议之后发生了什么）直接讲四渡赤水/会师细节。

### 2. 格式合规 `format_ok`

| 判 1 | 判 0 |
| --- | --- |
| 反馈 120–180 字；复盘 200–260 字；答疑 ≤100 字 | 超出或不足（按本节字数口径） |
| 纯文本一段话，无 Markdown、无小标题、无分点、无序号 | 出现 `**`、`##`、列表符号、代码块 |
| 无括号动作/神态描写（如“（叹气）”） | 出现动作描写或舞台说明 |
| 不含选项代号（`1A`、`2B`）、题号、关卡序号 | 复述“你选了 1A”“第一关”等 |
| 不含内部评判词：星级、层级、正确答案、最佳选项、得分、对错、标准答案 | 出现任一内部术语 |

**字数口径**：去掉空白与标点后，汉字、数字、字母各计 1 个字。开头“老陈：”计入；引号内标点不计。

### 3. 人格一致性 `persona_ok`

| 判 1 | 判 0 |
| --- | --- |
| 保持“老陈”基层指挥员口吻：口语化、像跟战友说悄悄话 | 变成老师讲课、评委点评或客服腔 |
| 只有 1935 年 1 月会场内外能知道的信息 | 全知视角（“后来事实证明……”）、现代概念、后续历史 |
| 复盘保持“党史推演导师”的谈心口吻，不贴画像标签 | 直接说“你是求实者/行动派”；逐题点评“第一关如何、第二关如何” |
| 不喊口号、不自我收尾（复盘结尾金句由系统拼接） | 自行追加口号或总结标语 |

### 4. 引导姿态 `guidance_ok`

| 判 1 | 判 0 |
| --- | --- |
| 偏差选择（tier1）：先共情/肯定动机中的合理处，再商量式给方向 | 说教、训斥、羞辱、直接判“你错了” |
| 表层正确（tier2）：先肯定抓住的部分，再点出“还差一层” | 只夸不引导，或把 tier2 当 tier3 吹捧 |
| 高质量（tier3）：明确肯定并讲清“为什么对”的思维价值 | 只复述选项，没有深化 |
| 复盘：肯定真实特质 → 点出一个成长方向 → 给可迁移启示 | 只夸、只批，或给出证据里不存在的特质 |

### 关于 NA

- 正常样本**不允许整行 NA**；四维都要判。
- 仅在生成失败（空回复、乱码、调用报错）时，整行填 `NA` 并在备注写故障原因；该行不计入维度分母，但必须计入“失败记录数”写进报告。

---

## 三、通过判定与门禁

1. **单条记录**：四维全为 1 → `verdict = 通过`；任一为 0 → `不通过`（`verdict` 只填“通过/不通过”）。
2. **单个样本稳定性**：5 次采样中 ≥4 次通过 → 稳定通过；否则该样本判失败。
3. **维度门禁**（由 `aggregate_scores.py` 计算）：

| 维度 | 门槛 |
| --- | --- |
| 史实忠实度 | ≥ 95% |
| 格式合规 | ≥ 95% |
| 人格一致性 | ≥ 90% |
| 引导姿态 | ≥ 90% |

4. 任一维度未达门槛，或存在不稳定样本 → 总体结论 `FAIL`，进入改 prompt / 收紧约束 → 重新采样 → 重新评分的闭环。

---

## 四、评分操作流程

1. 跑采样（真实端点，禁止把 dry-run 当数据）：
   ```bash
   cd 01_机器执行/02_L2_生成采样
   python run_sampling.py --endpoint "https://.../v1/chat/completions" --api-key "sk-..." --model "..." --repeat 5
   ```
2. 打开 `runs/L2_runs_<时间戳>.jsonl`，按 `sample_id + run_idx` 与 `02_人工执行/01_L2_人工评分/评分表.csv` 对应行；
3. 逐条读模型原文，四维各填 1/0，`verdict` 填“通过/不通过”，备注写**原文证据**（哪句史实错、哪处格式违规）；
4. 两人独立评分时，先分别填，再比对分歧；分歧行由第三人裁定，不得私下取平均；
5. 汇总：
   ```bash
   cd 01_机器执行/04_L4_数据分析
   python aggregate_scores.py
   ```
6. 产出 `L2_scores_<时间戳>.json`，把维度通过率与不稳定样本原样写进测试报告。

---

## 五、评分表字段说明（`评分表.csv`）

| 列 | 含义 |
| --- | --- |
| `sample_id` | 样本编号（已预填 30 × 5 行） |
| `category` | feedback / review / qa |
| `run_idx` | 第几次采样（1–5） |
| `fact_fidelity` / `format_ok` / `persona_ok` / `guidance_ok` | 1 / 0 / NA |
| `verdict` | 通过 / 不通过 / 空（未评） |
| `note` | 判定依据；0 分必须写具体原文 |

> 纪律：空表不会判为通过；`aggregate_scores.py` 在空表或全空 verdict 时只提示“未评分”。

---

## 六、答辩表述边界

- 可说：“30 条样本 × 5 次采样，四维通过率分别为 __，达/未达门槛 __。”
- 不可说：把采样数当评分数；把设计目标 30 条说成“已完成 30 条”而不给样本编号与评分文件。
- 每条结论必须能指到 `L2_runs_*.jsonl` 的具体行与 `评分表.csv` 的具体行。

## 附录：评分校准记录（T-2 天，正式评分前完成）

> 未完成校准不得开始正式评分。校准只用于对齐口径，不计入正式评分数据。

- 校准样本：1 条反馈（F 类）+ 1 条复盘（RV 类），全部评分员独立试评；
- 逐维对齐“什么算 0”，把争议例句补进本规则对应维度；
- 记录每位评分员与最终口径的分歧点，分歧在正式评分前解决。

**校准通过标准**：两名评分员对同一组样本的四维判定一致率 ≥ 90%，且对“常见 0 分例”的判定一致。未达一致率时先讨论再试评，不得直接开始正式评分。
